# 15 · 子页签、独立卡片与「CORRECT 位置锁定」

> 对应四项需求：
> ①把三个模式拆成三个子页签（按钮与内容同屏）②每个子页签内的卡片相互独立
> ③所有模式下 CORRECT 的位置锁定、不可改选其它组合 ④移除两个不使用反馈的策略。
> 相关代码：`templates/index.html`、`static/js/sandbox.js`、`static/js/human.js`、
> `static/js/combogrid.js`、`static/css/app.css`、`strategies/__init__.py`、`web/api.py`。

## 1. 三个子页签（为什么、怎么用）

**问题**：原来三种模式共用一个顶部工具条，
「所有策略各走一步」这类按钮在最上面，而它控制的卡片在下面——滚下去就点不到了。

**做法**：沙盒页改为**三个子页签**，每个页签有**自己的工具条 + 状态栏 + 卡片区**：

| 子页签 | 自己的控制栏 | 卡片 |
| --- | --- | --- |
| ① 手动试玩 | 种子、轮次上限、显示秘密、**把当前历史交给策略**、开新局、提交猜测、清空未锁定槽位 | 候选矩阵 / 猜测序列 / 对局历史 / 决策解释 |
| ② 策略自动 | 策略 + 参数、种子、轮次上限、显示秘密、开新局、**走一步**、**自动跑完** | 同上 |
| ③ 多策略对比 | 种子、轮次上限、显示秘密、开新局、**所有策略各走一步**、自动跑完；另有策略清单面板（增删/改参数） | 每个策略一张卡片 |

切页签只切显示；**每个页签各自保留自己的对局与槽位状态**，来回切不会丢。

## 2. 「卡片相互独立」的含义

每个子页签的卡片是**独立 DOM**（`data-role="matrix" / slots / history / explainBox`），
由 `sandbox.js` 里的 `SingleView` 实例各自渲染：

```js
state.views.manual   = new SingleView('manual');    // 自己的 game / slots / 矩阵 / 历史
state.views.strategy = new SingleView('strategy');
state.views.multi    = new MultiView();             // 每个策略一张卡，内部再独立
```

* 手动页签里点矩阵填槽，不会影响策略自动页签里的对局；
* 多策略页签里每张卡片的矩阵、历史、理由折叠面板互不影响；
* 三个页签共享的只有「候选矩阵组件」这份**渲染函数**，不含任何状态。

## 3. CORRECT 位置锁定（所有模式）

### 规则

**一旦某个位置被判为 CORRECT，这个位置就锁定**：

* 它的组合已经确定，界面不允许再把它改成别的组合；
* 候选矩阵里该组合打上 🔒（其余位置也不会再需要它——互异规则下它只出现一次）；
* 「让策略预测下一步」时，锁定位置保持原值（若策略建议与此不符，以锁定为准并提示）。

### 三处界面的具体表现

| 界面 | 表现 |
| --- | --- |
| 沙盒 · 手动试玩 | 槽位显示 🔒，点击该槽位会被拒绝并提示「已判定 CORRECT 并锁定…（如需改动请先撤销上一轮）」；矩阵点选会**跳过**锁定位置；「清空未锁定槽位」只清未锁定的，锁定位置保留 |
| 沙盒 · 策略自动 | 每轮结束刷新，锁定位置显示 🔒；矩阵同步显示锁定格 |
| 沙盒 · 多策略对比 | 每张卡片的槽位与矩阵都显示各自历史里的锁定位置 |
| 逐步猜测 | 待反馈猜测里，历史上已 CORRECT 的位置显示 🔒 并**自动预填 C**（人工录入的是事实，仍可改，避免误录无法纠正）；矩阵同步打 🔒；状态栏显示「已锁定 n 位」 |

锁定信息**只来自对局历史**（`feedback == CORRECT` 的位置），
所以撤销那一轮之后锁定会自动消失——界面状态永远等于历史事实，不需要额外记录。

### 实现

```js
// static/js/sandbox.js（SingleView）
lockedMap() {                       // 位置(1-based) → {combo, round}
  const map = new Map();
  (this.game?.history || []).forEach(r => (r.feedback || []).forEach((kind, i) => {
    if (kind === 'CORRECT') map.set(i + 1, { combo: r.guess[i], round: r.index });
  }));
  return map;
}
nextFreeSlot() { /* 跳过已锁定位置 */ }
```

矩阵组件新增 `locked: Set<"a-b">` 选项 → 渲染出 `.cg-locked` + 🔒 + 专门的 tooltip。

## 4. 移除两个不使用反馈的策略

`random`（均匀随机）与 `fixed_cycle`（固定循环平移）已删除，理由与影响面见
[03 文档 3.1 节](03_策略库说明.md)。要点：

* 它们**完全不使用反馈**，在 $45^{10}$ 的答案空间里不可能解出，只占轮次上限不产出对比信息；
* 它们会在**同一位置反复填同一个错误组合**，与真实可用策略的行为差距过大。
* 移除后策略库为 5 个：`naive_position`、`two_phase`、`position_entropy`、
  `adaptive_hybrid`、`particle_entropy`；`/api/strategies`、策略库页、实验台、
  默认计划（`DEFAULT_PLAN_KEYS`）与 `greedy_vs_adaptive` 预设同步更新。
* 历史日志（`Doc/08`、`Doc/06` 里的旧结果表）**保持原样**，那是当时真实跑出的数据。

## 5. 验证记录

浏览器实测（`http://127.0.0.1:5000`）：

* 三个页签互相切换，`manual/strategy/multi` 的显隐正确；每个单策略页签各有 100 个矩阵格 + 10 个槽位；
  多策略页签有 3 行策略清单。
* 策略自动（seed 7，two_phase）：6 轮解出 → 10 个槽位全部 🔒、矩阵 17 个锁定格（7 个非对角×2 + 3 个对角），
  状态栏「已锁定 10 位 · ✅ 已解出」。
* 手动试玩：按秘密顺序填满 10 槽并提交 → 1 轮全 CORRECT → 10 个位置锁定；
  点击锁定槽位被拒绝（提示「第 1 位已判定 CORRECT 并锁定…」）；「清空未锁定槽位」为禁用态（无未锁定项可清）。
* 多策略对比：自动跑完 → 3 张卡片各 10 个锁定槽位、共 51 个锁定矩阵格。
* 逐步猜测：全部标为 CORRECT 后显示 18 个锁定格 + 「已锁定 10 位 🔒」；撤销后锁定归零。
* 策略库页只剩 5 张卡片；实验台预设与参数控件正常。
* 自动化：`tests/test_ui_matrix.py` 新增「装配契约（三页签/三卡片容器/锁定类名）」与
  「两个策略确已移除」用例，单元测试 98 → **100 例全部通过**；`verify_api.py` 11/11。
