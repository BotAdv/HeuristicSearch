# 16 · 历史序列卡片、上三角矩阵与沙盒状态保持

> 本轮把沙盒的单策略界面**收敛成两张卡片**（候选矩阵 + 历史序列），
> 把矩阵的**可选区域砍到上三角**，并把整套界面状态**持久化到浏览器**。
> 相关代码：`templates/index.html`、`static/js/sandbox.js`、`static/js/combogrid.js`、`static/css/app.css`。
> 前序：[12 候选矩阵与状态着色](12_候选矩阵与状态着色.md)、[15 子页签与位置锁定](15_子页签与位置锁定.md)。

## 1. 「历史序列」卡片

单策略页签（手动试玩 / 策略自动）的卡片区现在只有：

```
┌─────────────────────────────┐   ┌──────────────────────────────────────────┐
│ 候选组合矩阵           45   │   │ 历史序列            2 轮   [开新局][提交猜测]│
│  · 只保留 a ≤ b 的上三角     │   │                           [让策略预测][清空槽位]│
│  · 左键选中 / 右键取消       │   │ ── 对局历史（上）────────────────────────  │
│  · 本轮选中：状态色高亮闪烁   │   │  #1  1·1 W  1·3 P  … 2·4 C   [理由]      │
│  ─────────────────────────  │   │ ── 猜测序列（下，1 行 10 列）─────────────  │
│   10×10 表格，45 格可点      │   │  1  2  3 … 10   （颜色 = 该位反馈）        │
└─────────────────────────────┘   └──────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────────┐
│ 决策解释：这一步为什么这么选（点「让策略预测」/「理由」时出现）                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

* **上半 = 对局历史**：每轮一行（10 位猜测 + 10 个反馈格），行尾「理由」按钮打开该轮的逐位依据。
* **下半 = 猜测序列**：`1 行 10 列`（`.slots.slots-row` → `grid-template-columns: repeat(10, …)`），
  与对局历史的每一行**同构**，所以上下对齐后能直接对位比较。
* 槽位颜色就是该位反馈（绿 `C` / 蓝 `M` / 紫 `P` / 红 `W`），`🔒` 表示该位已判定 CORRECT（锁定）。

### 卡片右上角的动作按钮

| 页签 | 按钮（左→右） | 说明 |
| --- | --- | --- |
| 手动试玩 | **开新局**（主按钮）/ 提交猜测 / 让策略预测 / 清空槽位 | 提交前必须先填满 10 位；清空只清未锁定位置 |
| 策略自动 | **开新局**（主按钮）/ 走一步 / 自动跑完 | 猜测完全由策略给出，槽位不可手工改 |

按钮由 `sandbox.js` 的 `ACTIONS` 表按页签生成（`id = "<页签>-<btnId>"`），
所以**按钮永远和被它作用的卡片同屏**；顶部参数栏里只剩下参数本身。

### 顶部参数栏（F9 收起/展开）

| 页签 | 参数 | 默认 |
| --- | --- | --- |
| 手动试玩 | 种子 / 轮次上限 / 显示秘密 / 让策略预测用哪个策略 + 该策略参数 | **收起**，只留一行提示 |
| 策略自动 | 策略 + 参数 / 种子 / 轮次上限 / 显示秘密 | 展开 |

快捷键：**F9** 切换当前页签的参数栏；**Enter**（焦点不在输入框时）等价于点「走一步 / 提交猜测」。

## 2. 候选矩阵：只保留上三角

$(a,b)$ 与 $(b,a)$ 是同一个组合，所以下三角整片重复。现在 `a > b` 的格子与
**被删除的 10 个组合**一样 `disabled`：不可点、不参与选中/锁定判定、不进 tooltip 的可选提示。
浏览器实测：100 格中 **45 格可点**（上三角含对角线），`cg-off` 45 格，
`cg-gone` 55 格（45 个下三角 + 10 个被删除组合的上三角格）。

实现：`renderComboMatrix(host, { triangle: 'upper', … })`（默认值就是 `'upper'`，
逐步猜测页同样适用）；`offTri = triangle === 'upper' && a > b`，`gone = removed.has(key) || offTri`。

**外观一致性**：`a>b` 与「被删除组合」共用同一条规则，避免出现两种灰：

```css
.cg-gone .cg-btn,
.cg-removed .cg-btn,
.cg-off .cg-btn { color:#4d5462; background:#14171d; border-style:dashed;
                  cursor:not-allowed; text-decoration:line-through; }
```

（曾给 `cg-off` 单独加 `opacity: .55`，实测计算样式与删除组合不同 → 已按需求统一。）

## 3. 点选交互

| 操作 | 效果 |
| --- | --- |
| 左键点矩阵格 | 填入**当前选定的位置**；没指定过就填**第一个空槽** |
| 连续左键 | **依次填入**：每填一格，选中位置自动移到下一个空槽 |
| 先左键点猜测序列的槽位 | **指定填入位置**（再点一次取消指定） |
| 右键点矩阵格 | **取消选择**：把该组合从猜测序列里清掉（可一次清多个位置） |
| 右键点猜测序列的槽位 | 清空该槽位 |
| 已锁定的位置 | 不可改选、不可清空（锁定由历史 `CORRECT` 推导，撤销上一轮自动解除） |
| 10 位已满且未指定位置 | 不静默覆盖，提示先指定要替换的位置或点「清空槽位」 |

**高亮**：本轮选中的格子**不再画蓝色框线**，而是给它的按钮加闪烁动画
（`.cg-cell.cg-picked .cg-btn { animation: cg-blink 1.1s ease-in-out infinite }`），
并按该格自身的状态色（`.mark-c/.mark-m/.mark-p/.mark-w`）做 `box-shadow` 呼吸。
猜测序列里“待填位置”仍有一圈细高亮——那是**位置指示**，与“组合被选中”是两件事。

## 4. 状态保持（刷新后数据不变）

```js
localStorage['hs.sandbox.v1'] = {
  v: 1,
  active: 'manual',                              // 当前页签
  toolbars: { manual: true, strategy: false },    // 参数栏是否收起
  ui: { manual: {seed, maxRounds, reveal, adviseStrategy, adviseParams},
        strategy: {seed, maxRounds, reveal, strategy, params},
        multi: {seed, maxRounds, reveal, plans:[{key,params}…]} },
  manual:   { gameId, slots, selectedSlot },       // 槽位、待填位置
  strategy: { gameId, slots, selectedSlot },
  multi:    { gameId },
}
```

* 写入时机：每次交互后 + `beforeunload`；读取时机：`boot()`。
* **对局本体在服务端会话里**，前端只存 `gameId`；刷新后按 id 重新拉取历史与秘密开关，
  再把本地槽位（可能含还没提交的手工编辑）回填。
* 会话失效（服务重启/过期）→ `restore()` 捕获 404，`clearGameInStore()` 抹掉失效 id，
  toast「上一局已失效（服务重启或会话过期），已重置」，页面照常可用。
* 手动改动猜测序列后，上一次「让策略预测」的解释面板会标注**【已过期】**，而不是直接消失。

## 6. 自测踩坑记录

* **`firstFreeSlot()` 返回 `-1`**：满行时提示语只判了 `!== null`，界面显示“下一个填入位置已指定为**第 0 位**”。
  加 `nextTarget()`（`idx >= 0 ? idx : null`）统一收口即可。
* **批量点格子时节点会失效**：`place()` 每次都 `renderPalette()` 重建矩阵，
  脚本里缓存的按钮已经是“脱离文档”的节点，点击仍会触发监听但读数会错位。
  自测脚本必须每次重新查询（`cellsOf()[i]`），否则会误判成 bug。
* **`new Function(src)` 语法自检**：改完大段 JS 先跑一次，比在浏览器里看白屏快得多。
