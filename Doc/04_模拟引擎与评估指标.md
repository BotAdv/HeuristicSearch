# 04 模拟引擎与评估指标

> 实现位置：`engine/simulator.py`（模拟）、`engine/metrics.py`（指标）、`engine/jobs.py`（后台任务）

## 1. 实验设计：配对比较

**问题**：不同策略的随机性来源不同（秘密序列 + 策略内部随机），如果各自独立随机，
差异会被方差淹没。

**做法**：

1. 用 `random.Random(seed)` 生成**一批**秘密序列 `secrets[0..n-1]`；
2. **所有策略**都跑这同一批秘密序列（配对设计）；
3. 策略自身的随机种子由 `(seed * 1000003 + game_index) & 0x7FFFFFFF` 派生，
   保证可复现且与秘密解耦；
4. 因此第 $k$ 局的 `rounds_a[k] - rounds_b[k]` 是有意义的配对差值，
   可以做**符号检验**（分布无关，不需要假设正态）。

```python
from engine.simulator import run_benchmark
report = run_benchmark(
    plan=[{"key": "position_entropy", "params": {"pick_mode": "split"}},
          {"key": "two_phase", "params": {"count_policy": "exact"}}],
    games=200, seed=20260920, max_rounds=60, secret_mode="random",
)
```

`plan` 里同一个 key 可以出现多次（不同参数），引擎会自动分配 `id`：
第一个是 `key`，之后是 `key#2`、`key#3`……避免结果互相覆盖。

## 2. 秘密序列生成方式

| `secret_mode` | 是否属于当前规则 | 含义 | 用途 |
| --- | --- | --- | --- |
| `distinct`（默认） | ✅ 规则内 | 从 45 个候选中**不重复**地取 10 个并打乱顺序 | 当前的正式规则 |
| `repeated` | ❌ 规则外对照 | 每个位置独立均匀采样，允许重复（旧规则，`random` 为别名） | 对比规则变更的影响 |
| `constant` | ❌ 规则外压力测试 | 同一条序列全为同一个组合 | 压测重数相关推理 |

### 2.1 规则外的秘密如何不把策略带偏

“秘密组合互异”是当前规则，策略里很多推理（重数恒为 1、已安置值全局传播）都建立在它上面。
用 `repeated` / `constant` 做对照时，模拟器会：

1. 以 `SequenceGame(secret=..., distinct=False)` 构造对局（跳过互异校验）；
2. 把每条计划参数的 `assume_distinct` 自动置为 `False`（`play_one` 里完成），
   策略于是降级到不依赖互异假设的版本。

因此**规则外实验不需要手改任何策略参数**，也不会产生无意义的“假设被违反”的假结果。
REST 接口里同样处理：显式传入秘密时按秘密自身的性质判断，否则按 `secretMode` 判断。

## 3. 指标口径（`engine/metrics.py`）

| 指标 | 定义 | 注意 |
| --- | --- | --- |
| `mean` | 平均步数（**截尾**：未解出的按 `max_rounds` 计入） | 与 `solveRate` 一起看 |
| `meanSolved` | 仅统计已解出对局的平均步数 | 解出率高时可作参考 |
| `median` | 中位数（线性插值分位数） | 抗离群 |
| `p90` / `p99` | 90/99 分位数 | 反映长尾 |
| `max` | 模拟中出现的最大步数 | 题目要求的“最坏步数” |
| `min` / `std` | 最小值 / 标准差 | — |
| `solveRate` | 解出率 | 随机/固定基线为 0 |
| `unsolved` | 未解出局数 | — |
| `histogram` | 步数直方图 | 前端柱状图数据源 |
| `meanMsPerGame` | 平均单局耗时（毫秒） | 计算成本 |
| `totalSec` | 该策略总耗时 | — |

**为什么不把未解出的样本丢掉**：直接删掉会让“跑得越久越占便宜”的策略看起来更好。
本项目采用**截尾**：未解出按上限计入，并单独给出解出率，两个数字一起读。

## 4. 统计检验

`pairwise_compare()` 对每对策略给出：

* `aWins` / `bWins` / `ties`：逐局谁更快；
* `meanDiff` = a 的平均步数 − b 的平均步数（**负数表示 a 更快**）；
* `pValue`：**双侧符号检验**的精确 p 值，零假设“两者无差异”（$p=0.5$）；
* `significant`：`pValue < 0.05`。

符号检验用精确二项分布计算（`math.comb`），不依赖正态近似，样本量小时也可靠：

$$
p = 2\sum_{i=0}^{\min(k,\,n-k)}\binom{n}{i}2^{-n},\qquad k=\#\{a\text{ 更快}\},\ n=aWins+bWins
$$

**读法**：p 值大（如 0.69）说明“差异不显著，可能只是噪声”，不要把它当成性能差异来解读。

## 5. 后台任务

`engine/jobs.py` 提供 `submit / get / list_jobs / cancel`：

* 用线程 + 信号量，最多 `HS_MAX_JOBS`（默认 2）个任务真正运行，其余排队，
  避免多任务抢 CPU 让“耗时”指标失真；
* `job.progress` 含 `done/total/current/message`，前端每 400 ms 轮询；
* `cancel_event` 传给 `run_benchmark`，在每局边界检查，可安全中断；
* 完成的报告同时写入 `runtime/runs/<job_id>.json`，可在实验台“历史运行”里查。

## 6. 导出

`GET /api/jobs/<id>/export?format=csv|json`

CSV 分三段（带 UTF-8 BOM，Excel 可直接打开）：

1. `per_game`：`strategy, game_index, rounds, solved, ms`；
2. `aggregate`：`games, mean, median, p90, p99, max, unsolved, meanMsPerGame, totalSec`；
3. `pairwise`：`aWins, bWins, ties, meanDiff, pValue, significant`。

## 7. 命令行为实验脚本

```powershell
python experiments/benchmark.py --games 200 --max-rounds 40
python experiments/benchmark.py --preset two_phase_vs_hybrid
python experiments/benchmark.py --preset objective_sweep --games 200
python experiments/benchmark.py --preset out_of_rule --games 45        # 规则外压力测试
python experiments/benchmark.py --preset repeated_rule --games 200     # 旧规则对照
python experiments/benchmark.py --all-presets --games 100
python experiments/benchmark.py --plan "position_entropy:pick_mode=split;explore_floor=2,naive_position:global_prune=true"
```

`--plan` 条目语法：`key` 或 `key:param=value;param=value`（值自动推断 int/float/bool/str）。
`--secret-mode` 可选 `distinct`（默认）/ `repeated` / `constant`。

预置方案：

| 名称 | 对应问题 | 内容 |
| --- | --- | --- |
| `greedy_vs_adaptive` | 问题 1 | 全部策略 + 固定循环 |
| `two_phase_vs_hybrid` | 问题 2 | 两阶段三种重数策略 vs 三种混合/自适应 |
| `misplaced_cost` | 问题 3 | 全局剪枝开关 / 取值准则 / 探测阈值消融 |
| `out_of_rule` | 问题 3b | 规则外压力测试（常数序列秘密） |
| `repeated_rule` | 规则对比 | 旧规则（允许重复）下的同一批策略 |
| `particle_scaling` | 问题 4 | 粒子数 32/96/512 + 目标函数 |
| `objective_sweep` | 问题 4 | 粒子策略四种评分目标 |

结果同时打印到终端、写入 `Doc/08_对局与模拟日志.md`、保存到 `runtime/runs/`。
