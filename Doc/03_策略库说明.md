# 03 策略库说明

> 实现位置：`strategies/`
> 所有策略共用一个接口，规则层对它们完全透明（策略拿不到秘密序列）。

## 1. 策略接口

```python
class Strategy:
    key: str            # 唯一标识，用于 API / 前端
    name: str           # 中文显示名
    description: str    # 说明
    tags: tuple         # 分类标签
    params_spec: tuple[ParamSpec, ...]   # 参数声明（前端自动渲染控件）
    max_rounds_hint: int                  # 建议轮次上限

    def __init__(self, seed: int | None = None, **params) -> None: ...

    def next_guess(self, history) -> List[Tuple[int, int]]:
        """history = [(guess, feedback), ...]；返回长度 10 的合法组合列表。"""

    # 可选钩子
    def reset(self) -> None: ...                              # 重置信念状态（子类须先 super().reset()）
    def observe(self, guess, feedback) -> None: ...            # 吸收一轮新反馈
```

`history` 中：

```python
guess    -> Tuple[Tuple[int,int], ...]   # 长度 10
feedback -> Tuple[str, ...]              # 长度 10，取值 CORRECT/MISPLACED/PARTIAL/WRONG
```

基类提供 `_sync(history)`：只把**尚未吸收**的轮次交给 `observe()`，
所以策略既可以增量维护状态，也在外部重置 history 时自动重建。

### 1.1 可选：决策解释钩子 `explain`（用于复盘）

策略可以声明 `self.explain = False`（默认）并实现解释输出，便于回答
“这一步到底是为什么选的”。已实现的是 `two_phase`：

```python
strategy = create("two_phase", seed=1, **params)
strategy.explain = True
strategy.next_guess(history)
strategy.last_decision
# {'round': 5, 'phase': 'A', 'phaseARounds': 5,
#  'support': {'inList': [...], 'inCount': 9, 'outCount': 31, 'unknownCount': 5, 'counts': {...}},
#  'candidates': [{'position': 1, 'size': 2, 'chosen': (2, 7),
#                  'reason': '批次分类：本位置候选集内已无剩余批次组合，改派批次里的 (2, 7)',
#                  'topCandidates': [(1, 10), (4, 10)]}, ...],
#  'batch': {...},      # 阶段 A：本批选了哪些未知组合、排序依据（覆盖面 / 使用次数）
#  'budget': {...}}     # 阶段 B：各支持集成员本轮开始/结束时的剩余副本数
```

约束（**必须遵守**，否则解释会污染结论，`tests/test_analyze_game.py` 会拦下来）：

* 钩子必须**纯只读**：`explain` 开关不能改变 `next_guess()` 的返回值；
* 每个位置的 `reason` 要**点明本轮实际填的组合**，不能只写“已锁定”这类泛化说法；
* 理由要与决策时刻的信念一致——分析器会在调用 `next_guess()` 前先 `_sync(history)` 再抓快照。

配套工具：`python experiments/analyze_game.py <gameId>`（详见 [11 文档](11_对局复盘_260920-00.md)）。

## 2. 共享信念工具（`strategies/belief.py`）

| 组件 | 作用 |
| --- | --- |
| `PositionBelief` | 逐位置候选集合 $C_i$；实现 2.2 节的四条推理；`global_prune` 与 `unique_values` 两个开关；`mask(i)` 返回位掩码缓存 |
| `PositionBelief.propagate_unique()` | **新规则专用**：把“已安置组合”从所有未定位置的候选中删除，迭代到不动点（依据：重数恒为 1） |
| `SupportTracker` | 每个组合的 `U/IN/OUT` 状态 + 精确重数；`unique_values=True` 时 `mark_in` 直接得到重数 1 |
| `NEIGHBOR_MASK` | 组合 → “与它共享至少一个对象”的组合位掩码，使共享关系统计变成 `O(1)` 位运算 |
| `shannon()` | 香农熵（bit） |

抽成共享组件的理由：这套推理很容易写错，而写错会导致“候选集合被误删”，
出现策略永远解不出来的隐性 bug。

### 2.1 `assume_distinct` 开关（重要）

所有用到互异推理的策略都有一个 `assume_distinct` 参数（默认 = `core.game.SECRET_DISTINCT`）：

* **规则内**（秘密组合互异）：保持 True，启用重数恒为 1 与全局传播；
* **规则外对照**（`--secret-mode repeated/constant`）：必须置 False，
  否则策略会套用不成立的假设、把真值误删。

模拟器会根据 `secret_mode` 自动注入这个参数（见 [04 文档](04_模拟引擎与评估指标.md) 第 2 节），
实验时不需要手改。

## 3. 内置策略一览

| key | 名称 | 类型 | 关键机制 | 平均步数¹ | ms/局¹ |
| --- | --- | --- | --- | --- | --- |
| `random` | 随机基线（不使用反馈） | 基线 | 均匀随机，忽略反馈 | 未解出 | 极快 |
| `fixed_cycle` | 固定循环（不使用反馈） | 固定 | 按候选表循环平移 | 未解出 | 极快 |
| `naive_position` | 朴素位置独立贪心 | 贪心 | 逐位消除 + 最少使用 | 6.775 | 0.86 |
| `two_phase` | 两阶段：先定支持集再定顺序 | 结构化 | 互异批次分类 + 置换求解 | **6.125** | 1.00 |
| `position_entropy` | 逐位置信息增益贪心 | 贪心+自适应 | `split` 探测 + 全局剪枝 | 6.260 | 1.81 |
| `adaptive_hybrid` | 自适应混合（探测/定位交织） | 混合 | 按 $|C_i|$ 分配探测/定位 | 6.550 | 1.00 |
| `particle_entropy` | 粒子滤波 + 全局最大熵 | 全局+概率 | 粒子后验 + 期望熵最大 | 7.045 | 76.1 |

¹ 数据来自 `--games 200 --seed 20260920 --max-rounds 40 --secret-mode distinct`（当前规则，详见 [06](06_实验结论与复现指南.md)）。
同一套代码在旧规则（`repeated`）下的数字完全不同，说明排名高度依赖规则。

### 3.1 `random` / `fixed_cycle`：下界参照

两者都**不使用反馈**。答案空间 $45^{10}$，它们实际上不可能解出，
存在的意义是量化“信息利用”的价值，并验证轮次上限保护机制正常工作。
`fixed_cycle` 是题目要求的“固定策略”代表。

### 3.2 `naive_position`：朴素位置独立贪心

* 状态：逐位置候选集合 $C_i$（含互异传播）+ 全局使用次数 `used[c]`。
* `CORRECT` 锁定；`MISPLACED` 仅把 $g_i$ 从 $C_i$ 删掉；
  `PARTIAL`/`WRONG` 按共享关系缩小 $C_i$。
* 取值：$C_i$ 中全局使用次数最少的组合（同分随机）。
* 参数：`global_prune`（默认 **False**，保持“朴素”语义）、`pick_mode ∈ {least_used, random, first}`、
  `assume_distinct`。
* **注意**：仅把 `global_prune` 打开就把 6.775 轮降到 6.620 轮；
  而在旧规则（允许重复）下同样的改动是 9.020 → 6.930（**−2.09 轮**）——
  新规则下“已安置值全局传播”接管了主要剪枝职责。

### 3.3 `two_phase`：先定支持集，再定顺序（当前规则下的最优策略）

阶段 A（集合确定）：

1. 每轮用一个**互异**的组合批次（最多 10 个不同组合），每个位置的反馈都能判定
   该位置的组合是否属于支持集（`C`/`M` ⇒ 属于，`P`/`W` ⇒ 不属于）；
2. 在“秘密组合互异”规则下，**支持集恰有 10 个元素且每个成员重数恒为 1**，
   所以只要已证实 10 个成员即可**提前结束探测**，无需任何常数序列探针；
3. `count_policy = "exact"` 只在规则外（允许重复）才有意义，
   规则内它与 `skip` / `auto_exact` 给出**逐局完全相同**的结果。

阶段 B（顺序确定）：把信念限制到支持集内，做“已安置值全局删除 + 轮内互异指派”：
按候选集合最小优先安置，优先使用**还剩副本**（互异规则下即尚未安置）的组合；
一轮内不会重复使用同一个组合。

参数：`count_policy ∈ {auto_exact, exact, skip}`、`probe_order ∈ {heuristic, sequential}`、
`assume_distinct`、`lock_known_positions`。

**实测**（200 局，规则内）：默认 **6.125 轮**，是全部策略中最快的；
把 `lock_known_positions` 关掉可再降到 **5.765 轮**（Δ=−0.360，p<0.0001 显著）——
因为那些已经确定的位置也被拿去试探新组合，每轮能多分类几个组合，阶段 B 的候选集更小。
保持默认为 True 的理由是可读性：**已确认的位置不会在下一轮忽然变样**，
人工逐步猜测时不会让人怀疑工具丢了信息。

### 3.4 `position_entropy`：逐位置信息增益贪心（实测最优）

三种取值准则（`pick_mode`）：

* **`split`（默认）**：在 $C_i$ 中优先选**尚未分类**的组合 $c$，使得
  “与 $c$ 共享对象 / 不共享对象”对 $C_i$ 的切割尽量均匀（最多 1 bit）。
  推导：若 $c\notin\mathrm{supp}(x)$，反馈只会是 `P`/`W`，正好按是否共享把 $C_i$ 一分为二；
  切割越均匀信息越多。若 $c\in\mathrm{supp}(x)$，反馈是 `C`/`M`，对 $x_i$ 几乎没有信息。
  由于“未测试组合属于支持集”的先验对所有候选近似相同，可以把“选哪个组合去探测”近似解耦。
* **`entropy`**：估计该位置 4 种反馈的概率分布，取熵最大者
  （$p_{eq}=1/|C_i|$，$p_{mis}=(1-p_{eq})q(c)$，$q(c)$ 由其它位置的候选集合估计）。
* **`least_used`**：选全局使用次数最少的组合。

另外两个关键设计：

* `global_prune`（默认开）：`P`/`W` 判定的组合从**所有**位置删除；
* **轮内互异**：同一轮里 10 个位置尽量分配给 10 个**不同**的未测试组合，
  使一轮完成最多 10 次支持集分类。

参数：`pick_mode`、`global_prune`、`explore_floor`（强制探测位置数，默认 0；
实测 >0 反而变差）、`assume_distinct`。

**实测**（200 局，规则内）：`split` 6.260 / `least_used` 6.510 / `entropy` 7.045。

### 3.5 `adaptive_hybrid`：探测/定位交织

不做严格分期：$|C_i| > \text{explore\_threshold}$ 的位置本轮用于**探测**未知组合，
其余位置用于**定位**。参数：`explore_threshold`（默认 1）、`max_explore`、
`global_prune`、`pick_mode`、`assume_distinct`。

**实测**（200 局，规则内）：阈值 1 / 10 / 45 分别得到 6.550 / 6.885 / 6.260 轮，
阈值 45（不显式探测）退化为 `position_entropy[split]`。
说明**显式探测配额并不带来收益**，能否利用全局互异约束才重要。

### 3.6 `particle_entropy`：粒子滤波 + 全局最大熵

1. 用粒子集合表示“与历史反馈完全一致的所有候选秘密序列”；
2. 每轮生成候选猜测池（粒子本身 / 逐位置众数 / 常数探针 / 边缘分布随机采样）；
3. 用粒子集合估计每个候选的**反馈分布**，选评分最优者。

参数：`particles`（默认 64）、`candidate_pool`（默认 32）、`min_particles`、
`refill_attempts`、`finish_particles`、`finish_bonus`、
`objective ∈ {entropy, entropy_correct, expected_remaining, expected_correct}`、`assume_distinct`。

实现要点：反馈判定与熵估计全部用 NumPy 向量化（`evaluate_particles()`），
单候选评分成本 $O(P\cdot 10)$；粒子不足时从**逐位置候选集合**重采样
（互异规则下逐位置抽不重复组合，保证真解一定在提议分布的支持内），再用完整历史过滤。

**实测**（200 局，规则内）：7.045 轮 / 75.3 ms，是最慢且最弱的有效策略；
粒子数 32/96/512 平均步数 7.035/6.855/7.105，耗时 71/100/469 ms —— 加粒子没有收益。

## 4. 新增一个策略

```python
# strategies/my_strategy.py
from typing import List
from core.game import Combo
from strategies.base import History, ParamSpec, Strategy

class MyStrategy(Strategy):
    key = "my_strategy"
    name = "我的策略"
    description = "一句话说明"
    tags = ("custom",)
    params_spec = (
        ParamSpec("alpha", "权重", default=0.5, type="float", min=0.0, max=1.0, step=0.05,
                  help="前端会把它渲染成数字输入框"),
    )

    def reset(self) -> None:
        super().reset()
        self.alpha = self.params["alpha"]

    def observe(self, guess, feedback) -> None:
        ...  # 增量更新信念

    def next_guess(self, history: History) -> List[Combo]:
        self._sync(history)
        ...  # 返回长度 10 的合法组合列表
```

然后在 `strategies/__init__.py` 的 `CLASSES` 里加一行即可：
REST 接口 `/api/strategies`、策略库页、实验台下拉、命令行 `--plan` 全部自动生效。

**约束**（`tests/test_strategies.py` 会检查）：

* 每个位置的输出必须是 `CANDIDATES` 中的合法组合（不能是已被删除的 10 个之一）；
* 长度必须正好 10；
* 相同 `(strategy, params, seed, secret)` 必须复现相同结果；
* 不同策略的 `key` 不能重复，同一策略的参数名不能重复。
