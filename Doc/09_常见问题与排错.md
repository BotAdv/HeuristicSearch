# 09 常见问题与排错

## 环境与启动

### Q1 `python app.py` 报 `ModuleNotFoundError: No module named 'flask'`

没有激活 conda 环境。请先 `conda activate flask_env`，或用完整路径
`conda run -p C:\Users\Leona\.conda\envs\flask_env python app.py`。
本项目的依赖只有 `flask>=3.0` 与 `numpy>=1.24`（见 `requirements.txt`）。

### Q2 端口 5000 被占用

```powershell
python app.py --port 8000
# 或
$env:HS_PORT=8000; python app.py
```

### Q3 端口通了但浏览器打不开 / 局域网访问不了

默认只监听 `127.0.0.1`。需要外部访问时：`python app.py --host 0.0.0.0`。
注意 Flask 开发服务器不应用于生产环境。

### Q4 改了模板/JS 但页面没变化

`app.py` 已设置 `TEMPLATES_AUTO_RELOAD=True` 且关闭静态缓存，刷新即可。
若仍不生效，检查浏览器强缓存（Ctrl+F5），或重启服务。

### Q5 Windows 控制台中文乱码

本项目在 `app.py` 启动时对 `stdout/stderr` 调用 `reconfigure(encoding="utf-8")`。
在 PowerShell 里跑脚本时建议先设置：

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
$env:PYTHONIOENCODING = 'utf-8'
```

## 规则与语义

### Q6 为什么秘密序列不允许重复？

这是**当前游戏规则**：秘密序列由 10 个**互不相同**的组合构成
（`core.game.SECRET_DISTINCT = True`）。它带来两条很强的可利用信息：

* 支持集恰有 10 个元素，且每个成员**重数恒为 1**；
* 一个组合一旦被定位，就可以从所有其它位置的候选中删掉。

同时它会显著改变策略排名（两阶段策略从最差变成最优），详见
[06 文档](06_实验结论与复现指南.md)。

### Q6.1 想恢复旧规则（允许重复）怎么做？

* 做实验：用 `--secret-mode repeated`（或实验台的“秘密生成方式 → 允许重复”）；
  引擎会自动关闭策略的互异推理。
* 彻底改回：把 `core/game.py` 里的 `SECRET_DISTINCT` 改为 `False`，
  并同步更新 `tests/test_game.py::TestSecretDistinctRule` 的预期。

### Q6.2 传入的 secret 报“按当前规则，秘密序列中的组合必须互不相同”

这是规则校验。要么改成 10 个互异的组合（例如让第 10 位换一个未用过的组合），
要么用 `secretMode=repeated/constant` 做规则外对照。
注意：**猜测序列**不受此限制，`guess` 里重复同一个组合是合法的。

### Q6.3 为什么 `two_phase` 的 `count_policy` 三种取值结果完全一样？

因为在互异规则下“重数恒为 1”由规则直接给出，`SupportTracker.mark_in` 不再需要探针，
`exact` 与 `skip` 于是退化为同一条路径。常数序列探针只在规则外（`repeated`，
或旧的允许重复分布）才有意义。

### Q7 为什么 `g_i` 与 `x_i` 明显共享元素，反馈却是 `MISPLACED` 而不是 `PARTIAL`？

这是规则的**优先级**决定的：只要 `g_i` 在秘密序列的其它位置出现过，无论它与 `x_i` 关系如何，
都判 `MISPLACED`。`PARTIAL` 只保留给“该组合是独苗”的情况。见
[02 文档 2.1 节](02_游戏规则与反馈定义.md)。

### Q7.1 提交猜测时报“组合 (1,5) 不在候选集合 S 中”

被预先删除的 10 个组合不属于 $S$，不能出现在猜测里。
`parse_combo()` 会先做顺序规范化（`(5,1)` → `(1,5)`）再校验，所以顺序写反没问题。

### Q8 提交猜测先后顺序有影响吗？

位置是有序的（第 1..10 位），反馈逐位对应。**组合内部**无序（$(a,b)=(b,a)$），
**序列位置**有序。

## 策略与实验

### Q9 某个策略一直解不出、`solveRate` 不是 100%

* 当前 5 个策略在规则内都能 100% 解出；若出现未解出，先看 `/api/jobs/<id>?result=1` 里的 `errors` 字段
  （策略抛异常会被逐局记录而不中断整批）；
* 若 `maxRounds` 设得太小（例如 3），也会出现截尾未解出。
* （历史）早期版本里还有两个**不使用反馈**的基线 `random` / `fixed_cycle`，
  它们必然跑满轮次上限，已在 2026-09-21 按需求移除（理由见 [03 文档 3.1](03_策略库说明.md)）。

### Q10 平均步数为什么等于 `maxRounds`？

说明该策略在这一批里**全部未解出**（截尾口径）。看 `solveRate` 就能确认。

### Q11 两个策略平均步数差 0.2 轮，算谁更好？

看两两比较表里的 `pValue`。本项目用双侧符号检验，`p<0.05` 才标记为显著。
实测中 0.2 轮级别的差异经常不显著（p ≈ 0.7），不要过度解读。

### Q12 为什么同一策略的两个参数变体没有互相覆盖？

引擎在 `assign_plan_ids()` 里给每个计划条目分配唯一 `id`（`key`、`key#2`……），
报告以 `id` 为键，`meta.plan` 里保留了对应的 `key` 与原参数。

### Q13 模拟跑太久 / 想中断

降低“每策略局数”，或点实验台的“取消”（后端在每个对局边界检查 `cancel_event`）。
另外 `HS_MAX_JOBS`（默认 2）限制同时运行的任务数，排队中的任务可立即取消。

### Q14 我改了 `core/game.py` 里的候选集合或规则开关，策略需要改吗？

不需要。所有策略都从 `core.game` 读取 `CANDIDATES` / `SECRET_DISTINCT`，
`PositionBelief` 与 `SupportTracker` 默认域也是它。
但改完要同步三处：

1. `tests/test_game.py` 里的基数断言（55 / 45）与 `TestSecretDistinctRule`；
2. 若关闭互异规则，请把 `SECRET_DISTINCT` 一并改为 `False`，
   这样策略默认就不再套用互异推理；
3. `Doc/02` 与 `Doc/06` 里的规则描述与实测数字。

### Q15 新增策略后前端看不到

检查是否把类加进了 `strategies/__init__.py` 的 `CLASSES`，以及 `key` 是否与已有策略重复
（`tests/test_strategies.py::test_registry_unique_keys` 会检查）。

## 性能

### Q16 哪个策略最贵？慢在哪？

`particle_entropy` 默认约 65 ms/局（96 粒子、32 候选池），其余策略均 < 2 ms/局。
慢的原因是每轮要对候选猜测池里的每个猜测做一次“全体粒子的反馈判定 + 熵统计”。
粒子数或候选池翻倍，耗时近似线性增长，而平均步数几乎不变。

### Q17 能让实验跑得更快吗？

* 减少局数（结论在小样本上就不稳定，建议 ≥ 200 局做结论）；
* 降低 `particles`（32 与 512 的步数差异不显著）；
* 一次别选太多策略变体（`two_phase` 的 `count_policy=exact` 在互异规则下最慢）。

## 逐步猜测模式（`/human`）

### Q20 秘密只有对方知道，能用这个系统研究吗？

能。用 `/human` 页面：策略出招，你对着真实秘密逐位录入反馈，直到全部 CORRECT。
服务端全程不知道秘密，但会保存完整的 `(猜测, 反馈)` 序列，可直接用于策略分析。
详见 [10 逐步猜测模式](10_逐步猜测模式.md)。

### Q21 反馈录错了怎么办？

* 页面会**自动校验**并给出警告（红色横条 + 历史里的 ⚠️ 行）；
* 点「撤销上一轮」（或按 `Backspace`）把那一轮退回并**恢复成待反馈状态**，改正后重新提交；
* 想要“错就拒收”，勾选「严格校验」：自相矛盾的反馈会被直接拒绝，且提示里会写明矛盾点。

### Q22 落盘的存档在哪？会覆盖吗？

* `runtime/games/<gameId>.json`：一局一个文件，不会覆盖；
* 同时追加到 `Doc/08_对局与模拟日志.md` 与 `Doc/_data/events.jsonl`；
* 页面右侧「已落盘对局」可以回看任意一局。

### Q23 策略给出的猜测里，已经标过 CORRECT 的位置为什么会变？

只有把 `two_phase` 的 `lock_known_positions` 关掉才会这样（默认是开着的）。
关掉后那些已确定的位置会被拿去做“试探新组合”，实测更快（−0.36 轮），
但人看着会觉得工具丢了信息，所以默认保持开启。

### Q24 警告会不会误报？

不会。校验器只使用**与秘密无关的必然规律**，并且在
`tests/test_human_mode.py` 里用“隐藏秘密 + 真实反馈”跑了 4 个策略共 120 局，
要求每一轮 `warnings == []` 才算通过。

## 文档与日志

### Q18 `Doc/08_对局与模拟日志.md` 变得很大

* 关闭**逐轮**明细：`$env:HS_DOC_LOG_ROUNDS=0`（模拟汇总仍会记录）；
* 完全关闭文档日志：`$env:HS_DOC_LOG=0`；
* 限制单次写入轮数：`HS_DOC_LOG_ROUND_LIMIT`（默认 400）。
* 日志是**追加**写入且带统一分隔结构，可以直接删除整段而不会破坏其它内容。

### Q19 `Doc/_data/events.jsonl` 是什么？

每行一条 JSON 事件，`kind ∈ {interaction, game, manual_round, simulation}`，
便于二次分析（例如统计某策略的逐轮反馈分布）。
